## Follow-up (2026-07-20) - recipe numbers showed literal "%g"

Reported by the user after actually looking at a building's panel in-game - exactly the live check flagged as unverified above, and it caught a real bug. `_format_number()` used `"%g" % value`, which looked like the right printf-style equivalent for "drop trailing zeros" but isn't actually a supported specifier for GDScript's `%` string-format operator (only `s/c/d/i/o/x/X/f/%` are - no `g`). It silently returned the literal, unprocessed string `"%g"` instead of raising any error, since GDScript doesn't validate format-string specifiers statically - so every recipe line read like "%g Wood -> %g Cabbage / cycle" instead of "0.5 Wood -> 1.1 Cabbage / cycle".

Also tried `String.num(value)` (default `decimals=-1`, documented as trimming to the minimum digits needed) as the fix - verified directly via a throwaway headless script (`--headless --path . --script res://fmt_test.gd`, deleted after) that it does *not* actually trim trailing zeros in this Godot build (`String.num(2.0)` → `"2.0"`, not `"2"`), and `decimals=0` rounds away real fractional values (`String.num(0.6, 0)` → `"1"`). Landed on formatting to 2 decimals then manually stripping trailing zeros and a bare trailing `.`: `String.num(value, 2).rstrip("0").rstrip(".")` - verified against every recipe currently in the catalog (0.5, 2.0, 1.1, 0.6, 2.2, 1.0, etc.) produces the intended "0.5"/"2"/"1.1" style output, and the actual `_recipe_text()` output for Cabbage Farm/Stone Mine/Lumber Camp/Brickmaker was spot-checked the same way. Full project still compiles clean after the change.
