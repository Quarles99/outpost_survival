- The more frequently villagers walk over the same tile the more progress it gets to becoming a dirt path tile.
- This naturally creates pathways on the most traveled routes
- Dirt paths give a small boost to movement speed for anyone traveling on them
- If left untraveled for awhile they will revert back to grass

## Completion write-up (2026-07-20)

**Refactored `IsoGround`'s dirt-tile bookkeeping first** (`scripts/iso_ground.gd`): before this pass, `mark_canopy`/`clear_canopy` (a mature tree's canopy, added earlier this session for [[Expand map size 4x]]) directly set a cell's `AtlasTexture.region`, with `clear_canopy` re-deriving from the static `_is_dirt()` noise/clearing/path check. Reusing that same pair of functions for foot-traffic wear would have let the two dynamic "why is this cell dirt" reasons clobber each other (a worn path under a tree that's since grown a canopy could incorrectly revert to grass the moment traffic there decayed away, or vice versa). Replaced with two independent Sets (`_canopy_cells`, `_worn_path_cells`) plus a single `_refresh_tile_region(cell)` that composes all three reasons (static noise/clearing/path, canopy, worn path) - `mark_canopy`/`clear_canopy`/new `mark_worn_path`/`clear_worn_path` all just flip their own Set entry and call it. `is_worn_path(cell)` exposes the foot-traffic-specific state for `Character` to read (see below) - deliberately distinct from "is this cell dirt for any reason," since canopy/ambient-noise dirt shouldn't grant the movement speed bonus, only an actual worn path should.

**Wear tracking (`autoload/world_grid.gd`, the natural home since it already held the `iso_ground` reference added for canopy):** `_path_wear: Dictionary` (`Vector2i -> current wear 0..WEAR_MAX`) only holds cells with any wear at all - decayed-to-zero cells are dropped entirely, so this stays bounded to "recently walked" cells rather than growing to cover the whole map over a long session. `register_foot_traffic(world_pos)` (called every frame `Character._move_to`'s loop is actually moving someone) bumps the current cell's wear by `WEAR_PER_SECOND * delta` and calls `iso_ground.mark_worn_path()` once it crosses `WEAR_PATH_THRESHOLD` (1.0, clamped at `WEAR_MAX` 2.0). A new `_process(delta)` on `WorldGrid` itself (an autoload `Node`, so `_process` runs continuously the whole session) decays every tracked cell by `WEAR_DECAY_PER_SECOND` regardless of whether it's currently being walked on - 10x slower than the gain rate on purpose, so a route crossed constantly stays worn while a one-off crossing fades back to grass in well under a minute, matching "if left untraveled for awhile" rather than reverting almost immediately. `get_speed_multiplier(world_pos)` returns `PATH_SPEED_MULTIPLIER` (1.15x) if that cell is currently a worn path, else 1.0.

**Wired into movement (`scripts/character.gd`):** `_move_to`'s per-frame loop - the one function every movement in the game already funnels through (hauling, commuting to a job, construction delivery, everything) - now calls `WorldGrid.register_foot_traffic(_base_position)` and multiplies `move_speed` by `WorldGrid.get_speed_multiplier(_base_position)` before calling `nav_agent.set_velocity()`. Because every citizen movement already goes through this one function, "anyone traveling on them" gets the speed bonus and contributes to wear for free - no per-work-loop changes needed anywhere else, and no separate "build a road" action exists (per the note's own framing - it emerges from ordinary traffic).

**Not persisted across saves**, matching every other `IsoGround` cosmetic state (ambient noise, canopy) - the ground is fully regenerated fresh every session rather than saved (see that class's own doc comment on why), and worn-path state is exactly the same kind of thing.
