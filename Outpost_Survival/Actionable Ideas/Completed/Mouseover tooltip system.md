## Completion write-up (2026-07-20)

**New autoload `TooltipManager`** (`autoload/tooltip_manager.gd`) - a generic "hover for 2s -> styled tooltip near the cursor" system, deliberately knowing nothing about resources or buildings specifically (`request(title, body)`/`cancel()` is the whole public API). Like every other autoload here it has no companion `.tscn` (autoloads can't have one - see `GameState`'s own Timer for the same constraint), so the Panel/Label tree is built in code in `_ready()`, styled to match `ui_theme.tres`'s default dark-panel-with-tan-border look. Renders on `layer = 20` so it's always on top of every other CanvasLayer UI panel and every world-space building, regardless of which one is being hovered.

**Wired into two call sites:**
- **HUD** (`scripts/hud.gd`): wood/stone icons, all seven Food-grid crop icons, and the Water/Population/Happiness/Day stat labels, via a small `_wire_tooltip(control, title_callable, body_callable)` helper - callables (not plain strings) so the tooltip always reflects live game state at the moment the 2s delay actually elapses, not whatever it was when `_ready()` first connected the signal. Replaced the old plain `tooltip_text` usage on these icons (Godot's default undecorated tooltip) rather than layering a second tooltip system on top of it.
- **Buildings** (`scripts/base.gd`): new `_wire_building_tooltip(building)` + `_tooltip_body(building)`, called from every place a building gets wired up (`_materialize_building`, the save/load restore loop, `_spawn_construction_site`, and the one-off fixed `$OutpostHall` wiring in `_ready()`). Every building class (Workstation and all its subclasses, House, OutpostHall, StorageFacility, Well) extends Area2D, so `mouse_entered`/`mouse_exited` already exist on all of them generically - no per-class branching needed, unlike the existing click-signal `_wire_*` helpers. Content is `description` (duck-typed via `building.get("description")`, since these classes share no common base beyond Area2D) plus, for a Workstation that isn't a ConstructionSite, the same `_recipe_text()` BuildingInfoPanel already shows on click plus a "Workers: n/max" line - condensed so the click panel and the hover tooltip describe a building consistently rather than two different ways.

**Filled in gaps this surfaced:**
- `OutpostHall`/`StorageFacility`/`Well` never had a `description` export at all - `BuildingCatalog`'s catalog entries for all three already *had* description text (written during the earlier "Building click UI" pass), but `_apply_option_properties`'s `node.set("description", ...)` was silently a no-op with nowhere to land it. Added the export to all three (matching `House`'s existing pattern of carrying its own copy since none of them extend `Workstation`), which makes that already-authored catalog text active for the first time.
- `Well` was a plain `Node2D` with no collision at all - the one building type with zero click/hover handling of any kind. Promoted to `Area2D` with a `CollisionShape2D` (`scenes/building/Well.tscn`, same 64x64 `RectangleShape2D` convention every other 1x1 building uses) specifically so it can participate in hover; still has no click meaning, only hover.

**Positioning bug found and fixed during verification:** the tooltip originally always opened down-right of the cursor (matching Godot's own default tooltip behavior). Since HUD's resource/stat rows all live in a panel anchored to the top-right corner, hovering an upper row (e.g. the Wood icon) opened the tooltip directly on top of the rows underneath it (Stone/Water/Population), confirmed by screenshot. Fixed by having `_position_at_mouse()` open away from whichever screen half the cursor is in - left of the cursor when it's in the right half, above when it's in the bottom half - so a tooltip never covers the panel it's describing regardless of which row is hovered.

**Verification:** `flatpak run org.godotengine.Godot --headless --path . --quit` clean after every change. Live-verified in an actual running window (`flatpak run org.godotengine.Godot --path . scenes/base/Base.tscn`, driven via `xdotool` mouse movement + a temporary debug screenshot key, removed after) rather than just compile-checked: confirmed a real 2.7s hover over the Wood icon shows "Wood / Chopped from trees by Lumber Camps. Used to build and feeds Mills. / Max capacity: 1000" positioned clear of the HUD panel, and a real hover over the Outpost Hall shows "Outpost Hall / The settlement's founding hall - the recruitment point and central stockpile." positioned clear of nothing (open space, so no flip needed). Not verified: every other individual building type's tooltip content (Farm/LumberCamp/StoneMine/Brickmaker/Workshop/TrainingGround/House/StorageFacility/ConstructionSite) - the wiring is generic and identical for all of them, and Outpost Hall's non-Workstation path plus a Workstation's recipe/worker-count path were both spot-checked, but a full sweep of all ~18 building types wasn't done live.
