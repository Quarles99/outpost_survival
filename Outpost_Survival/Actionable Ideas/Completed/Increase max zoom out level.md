## Completion write-up (2026-07-20)

**Max zoom-out:** `RtsCamera.zoom_min` (`scripts/rts_camera.gd`) lowered `0.5 -> 0.25` - doubles the previously-visible area again, on top of the map itself already being 4x bigger (see [[Expand map size 4x]]). Not lowered further than this first pass since going much lower starts to make individual villagers unreadably small (a handful of px tall) - the "realistic limits" this note's own phrasing asks for, not an arbitrary engine cap. `Docs/stats.md`'s Camera table updated (0.5x -> 0.25x).

**Localized/distance-based already true, not changed:** every villager/work sound already plays through a per-`Character` `AudioStreamPlayer2D` (SelectSound/GatherSound/LevelUpSound), and Godot's 2D positional audio already attenuates by world-space distance from the active `Camera2D` (which auto-acts as the audio listener - no `AudioListener2D` needed) using each player's default `max_distance`/`attenuation`, never overridden in this project. That already satisfies "quieter when offscreen" on its own; the gap this note actually surfaces is that Godot's built-in attenuation is **zoom-independent by design** - it only knows world-space distance, not how much of the map is currently on screen - so a villager sound played at max zoom-out (whole-map view) was exactly as loud as the same sound at max zoom-in, layering every citizen's ambient noise at once.

**Zoom-scaled fade (the actual gap):** added a new "World" audio bus (`default_bus_layout.tres`, registered via `project.godot`'s new `[audio]` section) sitting between Master and every ambient/incidental villager sound. `Character.gd`'s `GatherSound`/`LevelUpSound` (`AudioStreamPlayer2D`s in `Character.tscn`) are routed to it (`bus = "World"`); `SelectSound` deliberately stays on Master - it's direct feedback for a player's own deliberate click, the same "always audible regardless of zoom" treatment `UiSoundManager`'s new button-click sound gets, not a passive world event. `RtsCamera._update_world_audio_volume()` (called every `_process` frame, alongside the existing edge-scroll update) reads the actual interpolated `zoom.x` (not the target `_zoom_level`, so the fade tracks an in-flight zoom tween smoothly rather than jumping) and linearly fades the World bus from `0 dB` at `zoom_max` down to `-40 dB` (near-silent, without an abrupt hard mute right at the limit) at `zoom_min`. No combat-unit or building-specific sounds exist yet to route through the same bus (verified - `scenes/combat/` has none), so this covers every current diegetic sound in the game.

**Verification:** `flatpak run org.godotengine.Godot --headless --path . --quit` clean. Separately verified the bus layout actually loads via a throwaway `--headless --script res://verify_bus_test.gd` (printed `AudioServer.bus_count`/names/sends), confirming "World" registers as bus index 1 sending to Master, before deleting the script. Not verified by ear or by a live zoom-scroll - no live Godot session was running this pass. Worth a live check next session: zoom fully out and confirm villager work/level-up sounds fade to near-silent, then zoom back in and confirm they return to full volume, and confirm character selection's chime stays constant volume at any zoom level.

## Follow-up (2026-07-20) - "trees disappeared" turned out to be an empty default camera view

Reported by the user right after this landed. Investigated live (headless data check: `WorldGrid.get_trees().size()` == 160 immediately at boot, no errors; then two separate real-window launches with screenshots) and confirmed trees genuinely spawn and render correctly - one launch even showed a dense, clearly-visible forest around the Outpost Hall. The actual issue: `RtsCamera._ready()`'s starting `position` is a hardcoded guess (`get_viewport_rect().size / 2.0`) that only happened to line up with the Outpost Hall's own position on the old, much smaller 28x28 map (see `CLAUDE.md`'s Camera section) - on the new 56x56 map (this note's own max-zoom-out change, plus [[Expand map size 4x]]) that same fixed guess can land on an empty patch of grass with neither the Hall nor any citizen in view, purely depending on where groves randomly happened to scatter that run.

**Fix:** `Base._ready()` (`scripts/base.gd`) now calls `camera.focus_on($OutpostHall.position)` right after `_configure_camera_limits()` - the same `focus_on()` the Citizens panel already uses to snap to a clicked citizen - overriding `RtsCamera`'s own guess so every boot (new game or load) reliably frames the settlement regardless of map size, rather than a position that only worked by coincidence before.

**Verified live:** a fresh boot now shows the Outpost Hall centered on-screen with all 3 starting citizens visible directly below it, confirmed by screenshot.
