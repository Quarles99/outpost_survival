## Completion write-up (2026-07-20)

**Format unified across every resource row** (`scripts/hud.gd`): wood/stone (and the new Brick row, see below) and all seven Food-grid crop icons now share the exact same "icon: amount (workers)" label text (`_update_label_text`/`_update_food_display`). Wood/stone previously showed the fuller "50/1000 (+2.0/min)" format the food grid never had room for - capacity moved to the [[Mouseover tooltip system]] tooltip we'd just built (`_tooltip_body_for_resource`); rate was tried there too but dropped entirely per an explicit request, so the tooltip is just description + "Max capacity: N" now.

**Per-resource worker counts**: `Base._update_resource_worker_counts()` sums `active_workers` across every non-ConstructionSite `Workstation` post grouped by `resource_type`, called at the end of `_run_job_assignment()` (which already re-runs on every trigger that could change this - recruit/depart, post built/disabled/re-enabled, save loaded - see that function's own doc comment) and pushed to `HUD.set_worker_counts()` via the same direct-call pattern `set_happiness`/`set_day_label` already use, since only `Base` has the character/post roster.

**Idle workers**: same `_update_resource_worker_counts()` counts citizens with `assigned_post == null` and pushes it alongside the per-resource counts; a new `IdleLabel` row sits next to Population in the HUD, with its own tooltip explaining they haul automatically rather than sitting around doing nothing.

**Brick added as its own visible resource** (added mid-task per explicit request, alongside the rate-removal decision): Brick was tracked in `GameState.resources` and produced by Brickmaker but had no HUD row at all before this - added a `BrickRow` matching Wood/Stone's structure, icon via the already-existing `ResourceIcons.get_icon("brick")`.

**HUD overflow bug found and fixed** (confirmed with the user before implementing, since it meant restructuring HUD.tscn's layout, not just adding rows): adding the Idle and Brick rows pushed the top-right panel's content past its old hardcoded `offset_bottom = 560` height, and the Menu button started spilling out and overlapping the Food bar widget in the corner (confirmed by screenshot). Root cause: the panel was a plain `Control` with a fixed pixel height holding a `Panel` background + `VBoxContainer` sized to match - neither auto-sizes to content, so every row added was one row closer to overflowing. Fixed by converting the `Control` node itself to a `PanelContainer` (`theme_type_variation = &"Panel"` picks up `ui_theme.tres`'s existing dark-panel-tan-border style without touching that shared resource, since a plain `Panel` node elsewhere ignores `content_margin` and a `PanelContainer` elsewhere would pick up any margin added to the shared style - kept the 12/8/12/8 padding on a local `MarginContainer` instead of the shared stylebox specifically to avoid that risk) wrapping the `Rows` VBoxContainer directly - a `PanelContainer` not stretched by anchors on an axis auto-adopts its child's minimum size on that axis, so the whole box now grows/shrinks with content automatically. `hud.gd`'s onready paths all moved from `$Control/Rows/...` to `$Control/Margin/Rows/...` to match.

**Food bar widget repositioned** (the other half of that fix): since it's independently anchored to the bottom-right corner rather than actually anchored *to* the top panel's bottom edge, it doesn't automatically know how tall the top panel is - moved down (`FoodBarPanel.offset_top` -160 -> -104) and shrunk slightly (`FoodBarFrame.custom_minimum_size.y` 100 -> 50) to clear the new taller panel's actual measured bottom edge (597px, read via a temporary debug print rather than guessed from a screenshot) with a comfortable gap, verified by screenshot. This is still a hardcoded relationship, not a dynamic one - if the top panel's row count changes meaningfully in a future session (more resources, more stats), re-check this gap rather than assuming it still clears.

**Verification**: `flatpak run org.godotengine.Godot --headless --path . --quit` clean after every change. Live-verified via the same `xdotool`-driven screenshot workflow the tooltip system used (temporary debug key, removed after): confirmed the panel now hugs its content with no overflow, the Menu button no longer overlaps the Food bar widget, and Wood/Stone/Brick/every food icon shows "amount (workers)" with Idle: 3 visible next to Population on a fresh 3-citizen game (all three idle, since no job posts exist yet in a fresh save).
