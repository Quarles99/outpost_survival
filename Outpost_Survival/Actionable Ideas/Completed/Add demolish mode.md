## Completion write-up (2026-07-22)

Requested directly in chat, not a pre-existing backlog note: a HUD button + keybind that enters "Demolish Mode," where clicking a player-owned building instantly refunds its full cost, and clicking a natural feature (tree or rock) queues it for a villager to fully harvest before it disappears, with mining/lumberjacking skill giving a real productivity bonus. Two scope questions were resolved with the user up front: build a real mineable-rock system now (no such thing existed before this - `RockDecoration.tscn` was purely decorative), and make demolition-harvest a top-priority haul job any idle citizen can pick up rather than a full Gale-Shapley job-post integration.

**Click routing (`scripts/base.gd`):** two different paths, split by whether the target already has its own clickable Area2D. An earlier draft tried intercepting every left-click in `_input()` while `_demolishing` was true - rejected mid-design (caught by a second-opinion review before implementation) because that also silently kills every HUD button, including the Demolish toggle itself, since Control GUI input resolves after `_input()`. Buildings/construction sites instead get an `if _demolishing:` guard at the top of their *existing* click handlers (`_on_farm_clicked`/`_on_house_clicked`/`_on_training_ground_clicked`/`_on_building_info_clicked`/`_on_outpost_hall_clicked`) - pixel-accurate, since those already fire from a tuned Area2D. Trees/rocks have no Area2D at all, so a click on one falls through to `_unhandled_input` untouched, resolved there via `WorldGrid.local_to_grid` + the new `get_tree_at`/`get_rock_at` cell lookups.

**Buildings:** `_demolish_building(entry)` mirrors `_restore_placed_buildings`'s per-entry teardown (evict worker, `posts.erase`, reverse population/water/storage grants, unregister stockpile, release cells) plus a full refund - refund happens *before* reversing storage capacity, so demolishing a Storage Facility itself while stock is near the old cap doesn't clip part of the refund. `_cancel_construction_site(site)` is the same shape for an in-progress site, refunding only materials already delivered (`cost - materials_needed`). The Outpost Hall is blocked in its own click handler.

**Natural features:** new `WorldRock` class (`scripts/rock.gd`, `scenes/nature/Rock.tscn`) mirrors `WorldTree` but simpler - no growth/sapling/replant, a mined-out rock is gone for good. Sprite reuses `RockDecoration`'s own atlas region at 4x its scale (3.5 → 14.0, a later mid-conversation request) so it reads as a real boulder, not decorative pebble clutter. `WorldGrid` gained a parallel rock registry (`place_rock`/`get_rocks`/`clear_rocks`) plus two lookups needed by demolish-mode hit-testing that didn't exist for trees either (`get_tree_at`/`get_rock_at`), and `remove_tree` - an instant free-removal path for an immature sapling, which has to bypass `harvest()`/`depleted` entirely (a sapling's `wood_remaining` is 0, so `harvest()` would return 0 forever and never reach its own depletion check). `Base._scatter_initial_mineable_rocks()` scatters 20 boulders map-wide alongside the existing tree/decorative-rock/grass scatter.

**The harvest job (`scripts/character.gd`):** `Base.demolition_targets` holds marked `{"target", "resource", "skill_id"}` entries. `Character._find_demolition_job` is checked in `_find_haul_job` right after construction (ahead of routine output/input hauling - same "deliberate one-off player action beats routine busywork" priority construction already established), reusing `WorldTree`/`WorldRock`'s existing `claimed` field so a target still being worked by an *ordinary* Lumber Camp/Stone Mine assignment just waits. `_run_demolish_harvest` is `_run_lumberjack_loop`'s interleave-chop-and-haul shape applied to one fixed target instead of a nearest-available search, with no replant step - output/xp scaled by the worker's skill multiplier (the requested productivity bonus) and settlement happiness, same formula every other gather loop uses. `CHOP_SOUNDS`/`MINE_SOUNDS` (already existing pools) are reused for feedback, no new audio needed.

**HUD/keybind:** `DemolishButton` (`toggle_mode = true`) in `HUD.tscn`/`hud.gd`, `X` key (confirmed unbound via a full repo-wide keybind inventory). Exits via Esc, the button, or `X` - deliberately *not* right-click, since `Workstation` already gives right-click a global, always-on meaning (toggle `disabled`) that fires from its own Area2D regardless of demolish mode; unifying the two would only work when right-clicking empty ground and do something else entirely when right-clicking a building.

**Save/load:** new `"rocks"` section mirrors `"trees"` exactly. `demolition_targets` is explicitly cleared on load (not persisted) rather than left to rot - `_restore_trees`/`_restore_rocks` replace every node instance regardless, so a stale entry would only ever reference a dead node.

**Known gaps:**
- Tree/rock click resolution uses grid-cell math, not a pixel-tuned Area2D the way buildings get - the same minor "tall canopy vs. footprint cell" mismatch a real collider would avoid. If it ever feels imprecise in practice, giving `WorldTree`/`WorldRock` a small Area2D and routing them through the same click-handler pattern buildings use is the fix.
- A tree/rock marked for demolition but not yet claimed can still get fully harvested by an *ordinary* Lumber Camp/Stone Mine worker in the gaps between claim windows - harmless (no double-counting), just means the resource may end up credited as routine production instead of a demolition grant.
- "Preferred" skill assignment is opportunistic (whoever's free first benefits from the productivity bonus), not a guaranteed best-available-citizen dispatch.
- Mid-harvest demolition state isn't save-persisted - a save/reload simply un-marks the target; the player can re-mark it.
