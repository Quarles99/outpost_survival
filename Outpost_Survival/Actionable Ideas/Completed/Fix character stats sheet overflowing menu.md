## Completion write-up (2026-07-20)

**Root cause:** `SkillPanel` (`scripts/skill_panel.gd`/`scenes/ui/SkillPanel.tscn`) always shows all 13 skills (`SKILL_DISPLAY_ORDER`), each as its own full-width `"Skill Name: Lv N"` Label in a single-column `VBoxContainer`, inside a `Control` with a hardcoded fixed pixel height (328px, bottom-left anchored) - 13 skill rows plus Name/Task/Esc (16 rows total) comfortably exceeded that fixed height, clipping the bottom rows off-panel. Same root cause class as the HUD/BuildingInfoPanel/CropPanel/TrainingGroundPanel overflow bugs from earlier this session (a fixed-height `Control` that doesn't auto-size to content).

**Icons (new `scripts/skill_icons.gd`, `SkillIcons` class):** same static-catalog pattern as `ResourceIcons`. Five job skills that already map 1:1 to a single resource (`SkillTitles.TITLE_SKILLS`/`Workstation` subclasses) reuse that resource's own `ResourceIcons` entry instead of a second icon of the same thing - masonry (Brickmaker, stone->brick) shows the stone icon; farming/milling/baking/brewing show their crop/product icon. The remaining 8 (the 3 raw-gather trades, the 3 combat skills, and the 2 universal speed/strength skills) get a dedicated tool icon cropped from `items_sheet.png` (same sheet `ResourceIcons` already crops from) - sword (melee_combat), pickaxe (mining), axe (lumberjacking), a mace/warhammer stand-in (construction - no generic "builder's hammer" existed in the sheet), a gem-topped staff (spellcasting), a bow (archery, found among a cluster of curved-limb items easily mistaken for daggers at a glance), a leather glove (strength), and a boot (speed). Picked by direct visual inventory of the sheet at high zoom (ImageMagick point-filter upscale, since the source cells are only 16x16px) rather than guessing from thumbnails - two early picks (lumberjacking, at first pointing at a second mace instead of an axe) were caught and corrected this way before landing in code.

**Layout fix:** `SkillList` changed from a `VBoxContainer` to a 2-column `GridContainer`, each skill now an `HBoxContainer` (20x20 `TextureRect` icon + a bare `"Lv N"` Label) instead of one long text row - halves the row count (7 grid-rows instead of 13) on top of each row already being narrower. `Control` converted to a `PanelContainer` wrapping a `MarginContainer` (10px padding) around the content `VBoxContainer`, matching the exact pattern `BuildingInfoPanel`/`CropPanel`/`TrainingGroundPanel` already established for this - top-anchored instead of bottom-anchored (`offset_top = 376`, computed the same way those three did: the old bottom-anchored panel's top edge on a 720px viewport was already at 376, so this opens in the exact same place but now grows downward with content instead of clipping).

**Tooltips:** each skill icon wires `mouse_entered`/`mouse_exited` directly to `TooltipManager.request()`/`cancel()` (same generic system the Mouseover tooltip system pass built), showing the skill's display name (`SKILL_LABELS`) and a new one-line description (`SkillIcons.SKILL_DESCRIPTIONS`) - phrased in terms of the skill/action itself, not a repeat of `ResourceIcons`' own resource-flavored description, even for the 5 resource-backed skills.

**Bug found and fixed during live verification:** `var title := SKILL_LABELS[skill_id]` failed to compile at runtime ("Cannot infer the type of 'title' variable because the value doesn't have a set type") - `SKILL_LABELS` is an untyped `Dictionary`, so `:=` type inference has nothing to infer from. Never caught by the usual `--headless --path . --quit` compile check used throughout this session, because that only boots `MainMenu.tscn` (the project's `run/main_scene`) and quits immediately - `SkillPanel`'s script isn't actually parsed/compiled until `Base.tscn` loads for real. Caught instead by actually launching the game and clicking a citizen. Fixed with an explicit `var title: String = SKILL_LABELS[skill_id]`.

**Verification:** live-verified end to end via a real running window (`flatpak run org.godotengine.Godot --path . scenes/base/Base.tscn`, driven with `xdotool` mouse movement + `import` screenshots, closed after) - clicked a starting citizen (Cass) and confirmed the panel opens fully on-screen with no clipping, all 13 skills shown as a clean 2-column icon+level grid, and hovering the Farming icon for ~2.5s shows a tooltip reading "Farming / Grows crops at a Farm-family building. Higher level raises output per cycle." positioned clear of the panel. Not verified: every other skill's icon/tooltip individually (the wiring is generic and identical for all 13; Farming was spot-checked as the representative case).
